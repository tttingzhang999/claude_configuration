# 01 Work — Supplementary Rules

This file only takes effect when Claude touches files under `01 Work/**` (subdirectory memory), layered on top of the vault root `CLAUDE.md`.

## Project Directory Structure

Convention for `01 Work/projects/<PROJECT>/`:

Canonical reference layout: `01 Work/projects/_template/` (see its `README.md`). New projects follow it; `_template` is the authority when this table and the folders disagree.

| Subdirectory / File            | Purpose                                                                                                                   | Written by                                        | Frontmatter                                                                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `keypoint/`                    | Knowledge points (architecture, stakeholders, decisions, bug root causes)                                                 | Hand-written by user + skill suggestions          | `project`, `type: keypoint`, `source`, `tags`                                                                                  |
| `meetings/`                    | Meeting notes                                                                                                             | Hand-written by user, organized by `cook-meeting` | `participants`; `cooked` (bool gate — false = post-meeting LLM pass pending); `keypoints_synced`, `action_items_synced` (bool) |
| `SDD/{ticket}-{title}/`        | Dev four-pack (`proposal.md` / `design.md` / `tasks.md` / `specs/*.md`) — the state layer for the agentic-coding pipeline | propose·apply·verify skills                       | proposal: `type: proposal`, `ticket`, `title`, `propose_tier`, `status`, `design_approved`, `jira`                             |
| `Action Items - WIP.md`        | In-progress work items (single file, task syntax)                                                                         | user + `cook-progress`                            | `project`, `last_updated`                                                                                                      |
| `Action Items - Done.md`       | Completed items                                                                                                           | user + `cook-progress`                            | `project`, `last_updated`                                                                                                      |
| `Session Record/<YYYYMMDD>.md` | Per-day work notes (formerly auto-generated by `cook-daily-tasks`, now removed)                                           | Hand-written by user                              | `date`, `project`                                                                                                              |
| `tickets.base`                 | SDD progress board (scans `SDD/*/proposal.md` by `type == "proposal"`)                                                    | hand-written once                                 | —                                                                                                                              |

## Skill Write Policy

Don't break user's hand-written content:

- `keypoint/`, `Action Items - *.md` — no skill writes these **unattended**. Only `cook-progress` writes them, and only **after its preview → explicit-approval gate** (spoken-report mode appends to Action Items)
- `meetings/` raw → formal record — `cook-meeting` **previews first → waits for approval → then writes**
- Action Items additions/edits/removals — `cook-progress` **previews first → waits for approval → then writes**

## Action Items Scope

`Action Items - WIP.md` / `Action Items - Done.md` only record **Your Name's personal** work items:

- Tasks Your Name himself needs to execute
- Follow-ups where Your Name needs to proactively track whether others have completed something (format: `- [ ] 追蹤 @XXX 是否完成 YYY`)

**Not recorded**: PM-led items, overall team to-dos, work items for the ExampleClient contact point.

## Stakeholders

`01 Work/stakeholders.md` is the stakeholder directory (per project: name / role / email / domain / notes). Consult it in two situations:

- When Your Name mentions a person by name, look them up here to know who they are and which project they belong to.
- `cook-messages` reads it to strong-map a Gmail sender (email / domain) to a project.

## Reading the Real Repo Content

Project notes (`keypoint/`, `meetings/`, `Session Record/`) only describe the repo — they don't contain the actual code. When you need to see the **actual code** (verify an implementation, track down a bug, compare against the architecture), **use the `repo-router` skill** to resolve the project name into the real path on this machine before Read/Grep — don't just guess from the notes.

- The vault syncs across machines via iCloud, so repo absolute paths break when the username differs; `repo-router` restores them via `$HOME`-relative paths, which work on any machine.
- The mapping table lives at `.claude/skills/repo-router/repos.yaml`; after a new clone or relocation, run `uv run scripts/scan.py` to rescan.
- It can also be used to locate that repo's conversation history directory at `~/.claude/projects/<slug>`.

## Related Skills

- `cook-progress` — updates Action Items WIP/Done
- `repo-router` — resolves project names into real local repo paths for reading
