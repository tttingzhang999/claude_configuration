# Style Guide — Core（生成端）

> 用途：階段 3 初稿生成時載入。這份檔案只放「要對齊什麼」（正例）；「要避開什麼」（禁用詞、Rule A–K）在 `style-guide-verify.md`，由階段 4 的 critique agent 執行，生成時不需要讀。

## 核心定位

技術嚴謹 + 個人真實感 + 專業敘事的親近感。目標讀者是有經驗的工程師，語氣像跟一個技術背景的朋友認真討論問題。

假設讀者有基本技術能力，不解釋常識；但推理不跳步 — 讀者只靠文中資訊要能跟上每一步推導。

## 技術錨點與數字（幻覺防護，凌駕所有風格規則）

- 技術錨點（API、數字、設定、錯誤訊息）的來源只能是：使用者素材 / 取樣文章 / 驗證過的查詢結果
- 缺數據就寫 `[待補：___]` 佔位 — 禁止生成任何數字、版本號、定價

## 語言

- 中文是基底，負責敘事、情緒、反思。工程師日常口語講英文的動詞就寫英文；「檢查／設定／執行／回傳」這種非技術動詞用中文。技術與專有名詞不需要翻成中文

## Markdown 格式限制

- Heading：不用 H1（標題由 frontmatter `title` 承擔）；H2 是主要分段，可用「前言」「總結」等分類詞；H3 是內容標題
- 粗體：一個 section ≤2 處；blockquote：整篇 2–5 個
- 不用 emoji、不用斜體強調、不用 `---` 水平線
- 圖表：Mermaid

## 漸進式深化

引入技術概念時，從讀者已知的痛點或場景切入，不要從定義或歷史開始。

## 對比式教學

展示做法時，適時放「常見但不好的做法」和「更好的做法」對比。對比要有實質差異。

## 引用與內化

- 他人的方法論與觀點要內化成作者自己的論述寫出；正文不堆「某某說／某某認為／某某在某書中」，具名引用整篇 ≤2 處，其餘來源集中到文末「參考資料」
- 首尾呼應靠主題與意象，不在文中字面寫「回到開頭」
